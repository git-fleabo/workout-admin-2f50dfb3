# Skip saved plans for today — 14 October 2026

The screenshot identifies the saved practice plans under **Next workout** on Log. Their old Skip action updated the entire saved plan to lifecycle status `skipped`. The user intends to dismiss these plans for the current day while keeping them available for another day.

Workout and climbing quick-start cards now use **Skip today**. This writes the person's local calendar date to `suggested_workouts.dismissed_for_date` and leaves the plan's status, scheduled date, targets, programme links and routine configuration intact. The action requires an accessible pending or accepted plan and verifies that the update returned the intended row; a failed update reports an error rather than pretending the plan was skipped.

Today and both Log forms share a date-specific query and filter out only plans dismissed for that date. A successful skip immediately removes the card from their shared cached list, then refreshes it. The date is persisted in Supabase, so the dismissal survives a reload and applies across devices using the same calendar date. A previous day's dismissal no longer excludes the plan. Plan's weekly schedule remains independent of this daily display filter.

The migration adds one nullable date field under existing grants and RLS. It was applied to the verified linked project through the authenticated CLI after the MCP connection required reauthentication. The CLI's bulk migration push was not used because its dry run found older remote migration versions absent locally. Only this exact migration was applied and registered atomically; no existing migration history was repaired or reverted. Baseline and subsequent checks compared all 58 public/private data tables, excluding only the newly added null field. All existing row counts and values matched. No dismissal was set on an existing plan, and no training record was created or changed. Security advisors reported only the previously known disabled leaked-password protection warning.

Tests cover day-specific filtering and next-day return, preservation of the scheduled date and status, profile ownership filters, failed updates, weekly-schedule visibility and immediate removal in both Workout and Climb logging. Today, logger and scheduled-completion regression suites passed, as did targeted lint, TypeScript and the production build. The database field is live; repository UI changes still require the user's GitHub push, Lovable sync and publication. A published save-and-cleanup test of Skip today was not performed in this request.
